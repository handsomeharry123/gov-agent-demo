## 1. 产品定义

### 1.1 一句话定义

> **产业招商垂类大模型是一个「政策—空间—产业链」三域融合的招商决策智能体**：它把散落在政策文件、土地厂房台账、产业链图谱中的非结构化与结构化知识，转化为可计算、可推理、可溯源的决策依据，覆盖「产业诊断 → 目标挖掘 → 项目研判 → 选址匹配 → 政策测算 → 方案生成 → 履约监管」全链路，将招商从「人脉驱动的经验活」升级为「数据驱动的可计算决策」。

### 1.2 为什么通用大模型不够用

招商场景有三个特性，决定了通用大模型直接套壳必然失败：

| 问题             | 具体表现                                                     | 后果                                               |
| ---------------- | ------------------------------------------------------------ | -------------------------------------------------- |
| **不懂本地家底** | 本地有哪些政策条款、哪些空置厂房、产业链哪个环节缺链——这些内容不公开、高频变动、口径不一 | 模型一问三不知，或给出"全国统一模板"式的废话       |
| **不敢给结论**   | 招商决策涉及财政奖补、土地价格、税收返还测算，金额动辄千万级 | 通用模型泛泛而谈、编造条款，无人敢采信、无人敢担责 |
| **不能连数据**   | 数据在政策库、自然资源、市场监管、税务、园区物业等十几个系统里，互为孤岛 | 模型只能"聊"，不能"算"，更不能"办"                 |

**结论**：本产品的护城河不在模型本身，而在**三域知识资产 × 决策引擎 × 可信交互**的组合。

### 1.3 差异化定位：从"信息查询"到"决策生产"

```
第一代：招商信息门户    → 政策文件堆砌，人找信息      （已被验证低效）
第二代：企业数据库      → 名单 + 标签，人做匹配        （仍是工具，不是决策）
第三代：本产品          → 三域交叉推理，机器产出方案，人做判断与决策
```

关键跃迁：产品交付物不再是"一条信息"，而是**一份带依据、可审计的决策方案**。

## 2. 目标用户与角色价值

| 角色                       | 典型岗位                         | 核心痛点                                         | 产品给他的价值                             | 高频功能                     |
| -------------------------- | -------------------------------- | ------------------------------------------------ | ------------------------------------------ | ---------------------------- |
| **决策者**                 | 分管副市长、招商局长、园区董事长 | 家底不清、方向摇摆、汇报材料难产                 | 一张图看清产业家底与短板；一键生成诊断报告 | 产业诊断、招商态势看板       |
| **产业研究员**             | 产业研究员、规划院、智库         | 产业链图谱靠人工绘制，半年一更新，滞后严重       | 图谱自动构建与动态更新；缺口自动识别       | 产业链图谱、补链强链清单     |
| **一线招商专员**           | 招商局项目经理、园区招商经理     | 找项目靠人脉；谈项目不懂政策细节；算补贴靠 Excel | 目标企业自动推送；一企一策方案自动生成     | 目标挖掘、政策匹配、方案生成 |
| **载体运营方**             | 园区招商运营、资产经理           | 空置载体找不到租户；租户画像靠感觉               | 供需双向匹配；去化预测；租金定价参考       | 空间匹配、去化分析           |
| **项目服务专员**           | 代办中心、企业服务专员           | 政策申报材料繁杂，企业问什么都要翻文件           | 政策计算器 + 申报材料清单自动生成          | 政策申报助手                 |
| **企业选址方**（间接用户） | 企业投资总监、选址负责人         | 城市/园区信息不透明，跑断腿比选                  | 自助式选址比选与政策测算（对外版本）       | 选址比选、政策试算           |

**首要付费角色**：招商局长（决策者，买价值）+ 一线招商专员（使用者，验证价值）。产品设计应**先让一线专员用起来，再让局长看到结果**。

## 3. 核心场景定义（Job To Be Done）

按招商业务链路定义 8 个核心场景，每个场景明确：痛点 → 解法 → 交付物 → 量化收益。

### 场景 1：产业家底诊断

- **痛点**：本地有多少家企业、分布在哪些链条环节、产值/税收/用地效率如何，年底统计一次，数据陈旧且口径打架。
- **解法**：汇聚工商、税务（脱敏汇总）、专利、用地、用工数据，自动生成产业链地图 + 短板环节识别 + 与对标城市差距分析。
- **交付物**：《XX市产业诊断报告》（含产业链图谱、优势/短板清单、对标差距表、招商方向建议）
- **收益**：报告产出周期从 2 个月 → 1 天。

### 场景 2：目标企业挖掘（补链强链）

- **痛点**：招商目标靠展会名片、商会推荐、领导介绍，覆盖率低、命中率更低。
- **解法**：基于产业链缺口 → 反推目标环节 → 全网检索企业 → 用扩产/迁移/融资/中标信号排序 → 生成分级目标清单。
- **交付物**：《目标企业清单》（含企业画像、投资意向信号、匹配度评分、对接优先级、建议接触路径）
- **收益**：目标库规模提升 10 倍以上，有效线索率从 <5% 提升至 15%+（目标值）。

### 场景 3：项目落地可行性研判

- **痛点**：来了一个项目，要不要接？值不值？三天内要答复，只能凭经验拍脑袋。
- **解法**：输入企业名称/项目简介 → 自动尽调（工商、股权、专利、涉诉、产能、上下游） + 与本地产业契合度评分 + 落地效益测算（投资/产值/税收/就业） + 风险提示。
- **交付物**：《项目研判卡》（一页纸，含契合度评分、效益测算、风险等级、建议结论）
- **收益**：研判时间从 3–5 天 → 30 分钟，且结论有据可查。

### 场景 4：空间选址匹配

- **痛点**：企业要 2 万㎡单层厂房、承重 1 吨、配电 2000kVA，招商专员翻台账打电话，一天问不完。
- **解法**：结构化需求（面积/层高/承重/配电/排污/区位/价格）→ 多因子筛选载体 → 按适配度排序 → 生成比选方案（含优劣势、租金测算、政策叠加）。
- **交付物**：《选址比选方案》（3–5 个候选，含载体画像、适配度、成本测算、合规性校验）
- **收益**：选址响应从 1 天 → 5 分钟，候选覆盖完整度显著提升。

### 场景 5：政策匹配与奖补测算

- **痛点**：政策几百条，企业问"我能享受什么、能拿多少钱"，专员不敢答、算不准。
- **解法**：企业画像 × 政策条款图谱 → 全量匹配（含市/区/园区三级、跨部门组合） → 奖补金额测算 → 申报路径与材料清单。
- **交付物**：《政策匹配卡》+《奖补测算表》+《申报材料清单》
- **收益**：政策匹配从人工翻查数小时 → 即时；避免漏配（历史上平均漏配率 30%+）。

### 场景 6：「一企一策」招商方案生成（旗舰场景）

- **痛点**：谈一个重点项目，要做几十页方案：产业契合、载体方案、政策包、配套承诺、谈判要点。手工做一周。
- **解法**：三域交叉推理，一键生成结构化方案，支持人工在线编辑与版本管理。
- **交付物**：《XX项目一企一策招商方案》（含项目画像、产业契合论证、3 套载体方案、政策包测算、落地时间表、风险与谈判要点、承诺事项清单）
- **收益**：方案产出从 5 人日 → 1 小时，且口径统一、数据可复用。

### 场景 7：政策体检与竞对分析

- **痛点**：周边城市出了新政，我们政策还有没有竞争力？说不清。
- **解法**：对标城市政策库自动采集 → 条款级对比 → 竞争力评分 → 短板预警与修订建议。
- **交付物**：《招商政策竞争力分析报告》
- **收益**：政策响应速度从季度级 → 周级。

### 场景 8：落地项目履约监管

- **痛点**：项目签了约，投资到位多少、产值达成多少、亩均效益如何，年底才盘点，出问题来不及。
- **解法**：签约协议条款结构化 → 履约节点自动跟踪 → 偏差预警 → 亩均效益评价（与"亩均论英雄"改革衔接）。
- **交付物**：《项目履约看板》+《预警清单》+《亩均效益评价表》
- **收益**：从"事后盘点"变"过程管控"，降低闲置低效用地风险。

## 4. 产品总体架构

```
┌──────────────────────────────────────────────────────────────┐
│  交互层   Copilot 对话 │ 场景工作台 │ 报告工厂 │ API/插件      │
├──────────────────────────────────────────────────────────────┤
│  应用层   产业诊断  目标挖掘  项目研判  选址匹配  政策测算      │
│           方案生成  政策体检  履约监管  态势看板                │
├──────────────────────────────────────────────────────────────┤
│  能力层   ┌─────────────┬─────────────┬─────────────┐        │
│  (三域)   │  政策智能    │  空间智能    │  产业链智能   │        │
│           │  Policy     │  Space      │  Chain       │        │
│           └──────┬──────┴──────┬──────┴──────┬──────┘        │
│                  └──── 三域交叉推理引擎 ─────┘                │
├──────────────────────────────────────────────────────────────┤
│  模型层   垂类大模型（基座 + 领域增强）                        │
│           RAG 检索引擎 │ NL2SQL │ NL2Graph │ Agent 编排       │
│           溯源标注 │ 不确定性表达 │ 领域评测 Bench            │
├──────────────────────────────────────────────────────────────┤
│  知识层   政策知识图谱 │ 空间数字孪生 │ 产业链图谱             │
│           企业画像库 │ 招商案例库 │ 术语/口径词典             │
├──────────────────────────────────────────────────────────────┤
│  数据层   政策文件 │ 国土空间 │ 工商企业 │ 知识产权 │ 投资     │
│           招投标 │ 要素成本 │ 人才用工 │ 宏观产业 │ 舆情信号   │
└──────────────────────────────────────────────────────────────┘
         ↑ 数据治理：采集 · 清洗 · 实体对齐 · 更新 · 分级授权
```

**架构设计要点**：

1. **知识层是核心资产**——图谱不是"锦上添花"，而是三域交叉推理的前提。
2. **模型层不追求自研大模型**——聚焦领域增强与可信机制（溯源、计算、工具调用）。
3. **应用层按场景切分**——每个场景独立可验收，便于分版本交付与售卖。

## 5. 三域能力详细定义

### 5.1 政策智能（Policy Intelligence）

**数据对象**

| 对象               | 内容                                                   | 更新频率 |
| ------------------ | ------------------------------------------------------ | -------- |
| 政策文件           | 产业、科技、人才、金融、土地、税收、能耗等各类政策原文 | 实时/周  |
| 政策条款（原子化） | 适用对象、条件、奖补标准、上限、申报窗口、责任部门     | 随文件   |
| 申报指南           | 材料清单、流程、办理入口、办结时限                     | 季度     |
| 兑现记录           | 历史申报企业、金额、兑现进度                           | 月       |
| 上级政策           | 国家、省级政策（可争取资源）                           | 周       |

**知识建模**：政策知识图谱

```
(政策文件) —包含→ (条款) —适用→ (企业类型/行业/规模/区域)
            (条款) —给予→ (奖补类型:资金/税收/用地/人才/金融)
            (条款) —条件→ (指标门槛:投资额/产值/专利数/用工数)
            (条款) —冲突/叠加→ (其他条款)
            (条款) —依据→ (上位政策) —替代→ (旧条款)
```

关键：**条款级建模**（不是文档级），这是政策计算器的前提。

**原子能力**

| 能力         | 说明                                                         |
| ------------ | ------------------------------------------------------------ |
| 条款自动抽取 | 从 PDF/Word/OFD 政策原文中抽取结构化条款，人工复核后入库     |
| 政策计算器   | 输入企业画像 → 输出可享政策清单 + 奖补金额测算（含上限与叠加规则） |
| 政策体检     | 检测失效条款、冲突条款、空白领域（本地无政策但周边有）       |
| 竞对分析     | 与对标城市条款级对比，输出竞争力评分                         |
| 合规审查     | 新出台政策与上位法、公平竞争审查条例的冲突检测               |
| 申报助手     | 生成材料清单、填报模板、常见问题解答                         |

**输出物**：政策匹配卡、奖补测算表、申报材料清单、政策竞争力报告。

### 5.2 空间智能（Space Intelligence）

**数据对象**

| 对象        | 内容                                                         |
| ----------- | ------------------------------------------------------------ |
| 地块        | 位置、面积、规划用途、容积率、限高、出让状态、价格、成交记录 |
| 园区        | 主导产业、级别、配套、政策、入驻率、产值/税收/亩均效益       |
| 载体        | 厂房/楼宇/仓库：面积、层高、承重、配电、货梯、消防等级、租金、空置状态 |
| constraints | 能耗指标余量、排污指标余量、化工园区认定、安全防护距离       |
| 配套        | 交通（港口/机场/高铁）、物流、学校医院、人才公寓、商业       |

**知识建模**：空间数字孪生 + 载体画像

- 空间实体统一编码，与 GIS 地图绑定（“空间一张图”）
- 每个载体的**适配性标签**：适合哪些产业环节的硬性约束（如"不适合 VOCs 排放企业"）

**原子能力**

| 能力           | 说明                                                      |
| -------------- | --------------------------------------------------------- |
| 多因子选址     | 结构化需求 → 筛选 + 适配度排序（硬约束过滤 + 软约束打分） |
| 空间体检       | 空置率、去化周期、亩均效益、产业集聚度分析，识别低效用地  |
| 去化预测       | 基于历史去化与产业需求趋势，预测未来 12 个月供需          |
| 合规校验       | 项目落地与规划、环保、能耗、安全约束的冲突检测            |
| 空间一张图问答 | “全市层高≥9米的单层厂房有哪些？” → 地图 + 列表            |
| 租金/地价参考  | 周边可比案例价格区间与定价建议                            |

**输出物**：选址比选方案、载体推荐清单、空间体检报告、空间一张图。

------

### 5.3 产业链智能（Chain Intelligence）

**数据对象**

| 对象       | 内容                                           |
| ---------- | ---------------------------------------------- |
| 企业主体   | 工商、股权、分支机构、经营范围、规模、信用     |
| 产业关系   | 上下游供需、客户/供应商、投资关系、合作协议    |
| 创新能力   | 专利、软著、标准、研发机构、高新技术企业认定   |
| 经营信号   | 融资、中标、扩产备案、环评、用工招聘、土地摘牌 |
| 产品与技术 | 主营产品、技术水平、产能、进口替代/卡脖子环节  |
| 人才要素   | 产业人才分布、高校专业供给、薪酬水平           |

**知识建模**：产业链图谱（Chain Graph）

```
(产业链) —包含→ (环节) —承载→ (企业) —生产→ (产品/技术)
   (企业) —供应→ (企业)     (环节) —依赖→ (上游环节)
   (本地) —缺失/薄弱/优势→ (环节)
```

**原子能力**

| 能力         | 说明                                          |
| ------------ | --------------------------------------------- |
| 图谱问答     | “本地新能源汽车产业链哪些环节是空白？”        |
| 补链强链清单 | 自动识别缺失环节 → 输出优先招引环节与理由     |
| 目标企业挖掘 | 按环节 + 投资信号筛选，输出分级清单与接触路径 |
| 企业尽调     | 一键生成企业画像卡（含风险扫描）              |
| 落地影响推演 | 引入某企业对本地产业链的带动效应测算          |
| 产业对标     | 与对标城市产业链完整度、企业质量对比          |

**输出物**：产业链图谱、补链强链清单、目标企业清单、企业画像卡、产业诊断报告。

------

### 5.4 三域交叉：产品真正的护城河 ⭐

三域单独看，市面上都有同类工具（政策库、资产管理系统、企业数据库）。**真正的价值发生在三域交叉处**——招商决策本质上是一个多约束求解问题：

```
招商决策 = f( 产业链缺口, 空间供给, 政策工具, 要素成本, 企业诉求, 合规约束 )
```

**交叉推理示例**（旗舰场景：一企一策生成）

> **输入**：“苏州某精密结构件企业，拟在长三角扩产，需 2 万㎡单层厂房，员工 300 人，设备投资 1.5 亿。”

| 域         | 推理过程                                                     | 输出                        |
| ---------- | ------------------------------------------------------------ | --------------------------- |
| **产业链** | 识别为新能源汽车"电池结构件"环节 → 本地该环节仅 2 家企业，配套缺口明显 → 契合度 92 分，属**强链优先** | 产业契合论证 + 带动效应测算 |
| **空间**   | 硬约束筛选（单层、层高≥9m、承重≥1t、配电≥2000kVA、排污余量）→ 全市 4 宗载体匹配 → 按适配度排序 → 租金与购置成本测算 | 3 套选址方案 + 比选表       |
| **政策**   | 三级政策叠加（市级设备补贴 8% + 区级租金三免两减半 + 园区人才公寓）→ 3 年综合收益测算约 ¥1,860 万 → 申报路径与材料清单 | 政策包 + 测算表             |
| **风险**   | 环保指标余量不足需协调；同类项目周边城市竞争；产能过剩预警   | 风险清单 + 谈判要点         |
| **产出**   | 整合为一份《XX项目一企一策招商方案》，支持在线编辑与导出     | 可直接上会的方案文档        |

**产品设计要求**：交叉推理必须**显式展示推理链**（用了哪些数据、走了什么逻辑），而不是黑箱吐结论——这是政务场景可采信的前提。

## 6. 模型能力定义

### 6.1 垂类模型需在通用基座上增强的 6 项能力

| #    | 能力                 | 说明                                                         | 技术路径                                            | 验收标准                    |
| ---- | -------------------- | ------------------------------------------------------------ | --------------------------------------------------- | --------------------------- |
| 1    | **领域知识注入**     | 理解"亩均效益"“标准地”“飞地经济”"链长制"等招商术语与本地口径 | 继续预训练（领域语料）+ 图谱增强 RAG + 术语词典约束 | 领域术语理解准确率 ≥95%     |
| 2    | **长文档结构化理解** | 100+ 页政策汇编、可研报告、尽调报告                          | 长上下文 + 版面解析 + 分块索引                      | 条款抽取 F1 ≥90%            |
| 3    | **结构化数据能力**   | “近三年装备制造业税收前十企业” → 跨库查询与计算              | NL2SQL + NL2Graph + 指标计算引擎                    | SQL 执行正确率 ≥85%         |
| 4    | **强制溯源**         | 每条结论必须带出处（文件条款 / 数据表 / 时间），无出处不输出 | 检索绑定生成 + 引用校验 + 后置审核                  | 溯源正确率 ≥98%，幻觉率 ≤2% |
| 5    | **Agent 与工具编排** | 跨系统取数、调用计算器、生成文档、推送任务                   | Agent 框架 + 工具注册表 + 人机确认节点              | 多步任务完成率 ≥80%         |
| 6    | **审慎表达**         | 数据缺失、口径不确定时明确声明，不臆断                       | 不确定性标注机制 + 拒答策略                         | 人工评测达标                |

### 6.2 明确的"不做"边界（同等重要）

| 不做                             | 原因                                       |
| -------------------------------- | ------------------------------------------ |
| 不做最终审批决策                 | 只提供依据与建议，决策权在人；避免问责风险 |
| 不输出未经知识库核实的政策条款   | 政务场景"编造政策"是灾难级事故             |
| 不处理涉密数据与个人敏感信息出域 | 合规红线                                   |
| 不承诺"自动招商"                 | 招商是人与人的信任建立，机器只提供弹药     |
| 不追求通用聊天能力               | 聚焦场景，通用能力交给基座                 |

### 6.3 垂类评测集（Bench）

产品化必须配套自建评测集，建议 5 类，每类 ≥200 题，由业务专家标注：

| 评测集       | 题型示例                       | 目标                             |
| ------------ | ------------------------------ | -------------------------------- |
| 政策条款抽取 | 从政策原文抽取奖补标准         | F1 ≥90%                          |
| 政策匹配     | 给定企业画像，全量匹配可享政策 | 召回 ≥90%，准确 ≥85%             |
| 选址方案     | 给定需求，输出候选载体         | 候选完整率 ≥90%，排序合理率 ≥80% |
| 产业链问答   | 图谱关系查询与推理             | 正确率 ≥85%                      |
| 溯源与幻觉   | 结论是否有据、是否编造         | 溯源 ≥98%，幻觉 ≤2%              |

**机制**：每次模型/知识库更新，回归跑分，分数下降不允许上线。

| -------- | -------------------------------------- | ------------------ | -------- | ---------------- | --------- |
| 政策法规 | 政策文件、条款、申报指南               | 政府门户、部门内部 | 周       | 低               | 公开      |
| 国土空间 | 地块、规划、出让、不动产               | 自然资源局         | 月       | **高**（部门墙） | 内部      |

| 产业经济 | 产值、税收（汇总）、用电、用工         | 统计、税务、电力   | 季       | **高**           | 受限      |
| 创新能力 | 专利、软著、高企、研发机构             | 知识产权局         | 月       | 低               | 公开      |
| 市场信号 | 融资、招投标、扩产备案、环评           | 公开渠道采集       | 日/周    | 中               | 公开      |
| 要素成本 | 工业地价、厂房租金、水电气、物流、薪酬 | 采集 + 调研        | 季       | 中               | 公开      |
| 招商案例 | 历史项目、签约协议、履约数据           | 客户内部沉淀       | 月       | 中               | 敏感      |

**数据策略**：

1. **先易后难**——MVP 阶段只用公开数据 + 客户自愿提供的政策与载体数据，绕开最难协调的部门数据。
2. **数据换价值**——用"政策匹配结果""载体去化分析"反哺数据提供部门，形成交换正循环。
3. **明确数据责任人**——每个数据集指定责任部门与更新机制，避免"一次导入、永久过期"。

## 8. 交互形态设计

### 8.1 四种形态

| 形态               | 定位                                | 适用                         |
| ------------------ | ----------------------------------- | ---------------------------- |
| **① Copilot 对话** | 自然语言入口，降低使用门槛          | 日常问答、探索性查询         |
| **② 场景工作台**   | 卡片式流程，参数化输入 → 结构化输出 | 选址匹配、政策测算、方案生成 |
| **③ 报告工厂**     | 模板化一键生成，支持在线编辑与导出  | 诊断报告、研判卡、一企一策   |
| **④ API / 插件**   | 嵌入客户现有 OA、招商管理系统       | 存量系统增强                 |

**设计原则**：对话负责"问"，工作台负责"做"，报告工厂负责"交付"。不要用对话解决所有问题——复杂场景必须有结构化表单兜底。

### 8.2 三条交互铁律

1. **结论先行**：第一屏给答案，依据折叠可展开。领导不看推理过程，专员需要。
2. **依据可溯源**：每个数字旁必须有角标，点击跳转原文/原表。
3. **人机共编**：AI 生成的是**初稿**，必须支持人工修改、批注、版本管理——这是"可采纳"的心理关键。

## 9. 产品原则

| #    | 原则                   | 说明                                                         |
| ---- | ---------------------- | ------------------------------------------------------------ |
| 1    | **可溯源高于一切**     | 政务场景中，一条不可追溯的结论会摧毁整个产品的信任。宁可答"查不到"，不可"猜一个"。 |
| 2    | **人机协同，人做决策** | 产品定位是"参谋"不是"指挥"，明确决策权归属用户。             |
| 3    | **一地一策，可配置**   | 每个城市的产业基础、政策体系、审批流程不同，产品必须支持本地化配置而非硬编码。 |
| 4    | **数据闭环，越用越准** | 用户反馈（采纳/修正/拒绝）必须回流，持续优化匹配与排序。     |
| 5    | **合规与安全优先**     | 数据分级、权限最小化、操作留痕，满足政务审计要求。           |

## 10. 指标体系

### 北极星指标

> **月度"被采纳并进入实质推进"的项目数**
> （即：模型输出的研判/方案被用户采纳，且项目进入实地考察或谈判环节）

选择理由：它同时反映**使用深度**（不是点了多少）与**业务价值**（不是生成了多少份废纸）。

### 分层指标

| 层级     | 指标                         | 目标             |
| -------- | ---------------------------- | ---------------- |
| **使用** | 周活跃用户数 / 目标用户数    | ≥60%             |
|          | 人均周完成任务数             | ≥8               |
| **质量** | 结果采纳率（采纳/修改/弃用） | 采纳 ≥50%        |
|          | 溯源正确率                   | ≥98%             |
|          | 幻觉率                       | ≤2%              |
| **效率** | 单任务平均耗时下降           | ≥70%             |
|          | 报告产出周期                 | 从月级 → 天级    |
| **业务** | 目标企业线索转化率           | 提升 2–3 倍      |
|          | 政策应享尽享覆盖率           | ≥95%（避免漏配） |
|          | 载体去化周期                 | 缩短（V2 验证）  |

## 11. 商业化与交付模式

### 11.1 客户分层与价值主张

| 客户              | 付费动机                   | 预算来源              | 典型规模 |
| ----------------- | -------------------------- | --------------------- | -------- |
| 地市级政府        | 全市产业统筹、招商考核压力 | 数字经济/智慧城市专项 | 大       |
| 区县级 / 园区     | 招商指标、载体去化         | 园区运营预算          | 中       |
| 产业地产商        | 去化效率、精准招商         | 市场化预算            | 中小     |
| 银行/基金（延伸） | 项目风控、投贷联动         | 科技预算              | 待验证   |

### 11.2 计费结构

```
平台基础费（年度）        → 席位 + 部署
+ 数据服务包              → 产业链图谱构建、政策库治理（一次性 + 年维护）
+ 定制开发                → 与本地系统对接、本地口径配置
+ 运营服务                → 数据更新、知识运营、使用率提升（可选，强推荐）
```

**关键建议**：**必须包含运营服务**。政务客户买系统但不用的概率极高，没有数据运营与推广陪伴，产品会在半年内变成僵尸系统。

## 14. 待确认事项（需决策）

1. **首条重点产业链选哪一条？** 建议选本地最有基础、数据最完整的 1 条做深，而非全面铺开。
2. **首要客户是市级统筹还是园区单点？** 影响架构优先级（市级重统筹诊断，园区重去化与匹配）。
3. **是否需要对企业端提供服务门户？** 涉及对外数据授权与合规边界。
4. **模型基座选型与部署方式**：国产化要求、算力资源、私有化程度。
5. **是否接入履约监管模块？** 涉及与"亩均论英雄"等既有改革衔接，业务敏感度较高。
6. **数据运营由我方、客户还是第三方承担？**
